PHẦN 3: TRUY VẤN NỀN TẢNG & GIÁ TRỊ NULL THỰC HÀNH T-SQL

3. Kỹ thuật Truy vấn Nền tảng & Logic 3 Giá trị

Truy vấn lọc dữ liệu cơ bản trong SQL Server sử dụng mệnh đề SELECT ... FROM ... WHERE. Hiểu rõ logic 3 giá trị (True, False, Unknown) là điều kiện tiên quyết để tránh bẫy dữ liệu khi xử lý giá trị NULL.

3.1 Cú pháp lọc chuỗi, đoạn & tập hợp

-- 1. LIKE: Tìm sản phẩm mã bắt đầu bằng 'B' và tận cùng bằng '01'
SELECT MASP, TENSP, GIA FROM SANPHAM WHERE MASP LIKE 'B%01';

-- 2. BETWEEN: Lọc trong đoạn đóng [5000, 35000]
SELECT MASP, TENSP, GIA FROM SANPHAM WHERE GIA BETWEEN 5000 AND 35000;

-- 3. IN: Thuộc tập giá trị rời rạc
SELECT MASP, TENSP, NUOCSX FROM SANPHAM WHERE NUOCSX IN (N'Viet Nam', N'Nhat Ban');

3.2 Logic 3 giá trị (3-Valued Logic) & Bẫy NULL

NULL thể hiện thông tin chưa biết hoặc không tồn tại, không phải là số 0 hay chuỗi rỗng ''. Mọi phép so sánh bằng toán tử thông thường với NULL (như = NULL hoặc != NULL) đều trả về UNKNOWN, và mệnh đề WHERE sẽ loại bỏ tất cả các dòng có kết quả UNKNOWN.

Bắt buộc dùng IS NULL
-- SAI: Luôn trả về 0 dòng!
SELECT * FROM KHACHHANG WHERE SODT = NULL;

-- ĐÚNG: Cú pháp chuẩn SQL Server
SELECT * FROM KHACHHANG WHERE SODT IS NULL;

3.3 Sắp xếp kết quả với ORDER BY

ORDER BY luôn nằm ở cuối cùng của câu truy vấn. Khi sắp xếp theo thứ tự tăng dần (ASC), SQL Server coi NULL là giá trị nhỏ nhất và đặt ở đầu kết quả.

4. Phép kết (JOIN) & Dòng thực thi (Execution Trace)

Phép kết kết nối các hàng từ hai hay nhiều bảng dựa trên cột chung. Hiểu rõ dòng thực thi bên trong Database Engine giúp lập trình viên viết truy vấn tối ưu và dự đoán chính xác kết quả đầu ra.

4.1 Worked Example: Truy vấn kết nối nhiều bảng

Yêu cầu: In ra danh sách các hóa đơn mua hàng trong ngày 2024-10-15 gồm: Tên khách hàng, Số hóa đơn và Trị giá, sắp xếp theo Trị giá giảm dần.

SELECT KH.HOTEN, HD.SOHD, HD.TRIGIA
FROM HOADON HD
INNER JOIN KHACHHANG KH ON HD.MAKH = KH.MAKH
WHERE HD.NGHD = '2024-10-15'
ORDER BY HD.TRIGIA DESC;

4.2 Dòng thực thi chi tiết (Execution Trace)

2. WHERE

INNER JOIN vs LEFT JOIN

INNER JOIN chỉ giữ lại các dòng có khóa khớp ở cả hai bảng. Nếu khách hàng chưa từng có hóa đơn, họ sẽ bị loại. Dùng LEFT OUTER JOIN nếu muốn giữ lại toàn bộ khách hàng và hiển thị NULL ở các cột hóa đơn.

4.4 Kỹ thuật Tự kết (Self-Join) & Gom nhóm (GROUP BY)

Tự kết (Self-Join) là phép kết một bảng với chính nó để giải quyết các mối quan hệ đệ quy (như nhân viên - quản lý). Gom nhóm (GROUP BY) phân chia tập dữ liệu thành các nhóm độc lập để tính toán thống kê (căn cứ TECH-A02).

4.4.1 Self-Join: Tìm Trưởng bộ môn / Người quản lý

-- Lấy tên Giáo viên và Tên Giáo viên quản lý trực tiếp
SELECT GV.MAGV, GV.HOTEN AS TenGiaoVien, QL.HOTEN AS TenNguoiQuanLy
FROM GIAOVIEN GV
LEFT JOIN GIAOVIEN QL ON GV.MAGVQL = QL.MAGV;

4.4.2 Cơ chế gom nhóm với GROUP BY

Mọi thuộc tính xuất hiện trong danh sách SELECT mà không nằm bên trong một hàm kết hợp (như COUNT, SUM, AVG, MIN, MAX) đều bắt buộc phải được khai báo trong mệnh đề GROUP BY.

-- Thống kê số lượng sản phẩm và giá trung bình theo từng nước sản xuất
SELECT NUOCSX, COUNT(*) AS SoLuongSP, AVG(GIA) AS GiaTrungBinh
FROM SANPHAM
GROUP BY NUOCSX;

Nếu viết SELECT NUOCSX, TENSP, COUNT(*) FROM SANPHAM GROUP BY NUOCSX;, SQL Server sẽ báo lỗi Msg 8120 vì trong mỗi nhóm NUOCSX có nhiều TENSP khác nhau, máy chủ không thể biết lấy tên nào để hiển thị vào 1 ô kết quả duy nhất.
